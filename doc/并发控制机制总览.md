## 一、双重翻译机制

这个项目的"双重翻译机制"包含两层含义：

### 1. 翻译缓存机制（第一层）

**位置**: `util/translator.ts:542-566`

**实现原理**:
```typescript
// 缓存键格式: "目标语言::JSON内容"
private getCacheKey(chunkText: string, targetLang: string): string {
  return `${targetLang}::${chunkText}`;
}
```

**核心特性**:
- 使用 Map 结构存储已翻译内容，避免重复调用 API
- 启动时从 `cache/translation_cache.json` 加载历史缓存
- 每次翻译成功后立即持久化到文件
- 缓存命中率直接减少 API 调用，提升性能和稳定性

**缓存加载** (`util/translator.ts:542-553`):
```typescript
private loadCache(): void {

    const data = fs.readFileSync(CACHE_FILE, "utf8");
    const parsedCache = JSON.parse(data);
    this.cache = new Map(parsedCache);
    console.log(`✅ 已从 ${CACHE_FILE} 加载 ${this.cache.size} 条缓存。`);
  }
}
```

**缓存保存** (`util/translator.ts:558-566`):
```typescript
private saveCache(): void {
  const cacheArray = Array.from(this.cache.entries());
  fs.writeFileSync(CACHE_FILE, JSON.stringify(cacheArray, null, 2), "utf8");
  console.log(`💾 已保存 ${this.cache.size} 条缓存到 ${CACHE_FILE}。`);
}
```

```typescript
async function processNextQueuedTask() {
  const nextTask = await getNextTranslationTask();
  if (!nextTask) return;

  const lockAcquired = await acquireLock(nextTask.projectId);
  if (!lockAcquired) {
    // 锁被占用，稍后重试
    setTimeout(() => processNextQueuedTask(), 1000);
    return;
  }

  // 执行翻译任务
  await runI18nSync({...});

  // 释放锁后递归处理下一个任务
  releaseLock(nextTask.projectId);
  setTimeout(() => processNextQueuedTask(), 1000);
}
```

## 三、并发稳定性保障机制

### 1. 项目级隔离

**位置**: `routes/i18n.ts:44-62`

```typescript
const lockAcquired = await acquireLock(projectId || "unknown");
if (!lockAcquired) {
  // 同一项目的请求进入队列，不同项目可并发
  const taskId = await addTranslationTask({...});
  return { message: `任务已加入队列。任务ID: ${taskId}` };
}
```

**优势**:
- 不同项目的翻译任务可以并发执行
- 同一项目的多个请求串行化，避免资源竞争
- 每个项目独立的锁文件，互不干扰

### 2. 多语言并发翻译

**位置**: `util/syncI18n.ts:300-324`

```typescript
const CONCURRENT_LIMIT = 17;  // 同时翻译17种语言
const langChunks = chunkArray(langs, CONCURRENT_LIMIT);

for (const chunk of langChunks) {
  await Promise.all(chunk.map(lang => processSingleLang(lang)));
}
```

**稳定性考虑**:
- 限制并发数为 17，避免过多并发导致 API 限流
- 分批次执行，每批完成后再执行下一批
- 单个语言失败不影响其他语言

### 3. 批次翻译控制

**位置**: `util/syncI18n.ts:60, 245`

```typescript
const CHUNK_SIZE = 50;  // 每批翻译50个键
const keyChunks = chunkArray(keysToTranslate, CHUNK_SIZE);
```

**原因**:
- 避免单次 API 请求 JSON 过大导致超时
- 减少单次失败的影响范围
- 提高翻译成功率

### 4. 故障恢复机制

**锁超时自动恢复** (`util/index.ts:168-175`):
- 如果进程崩溃，锁文件会在 1 分钟后自动失效
- 新请求可以强制删除超时锁并重新获取

**心跳续租防止误判** (`util/index.ts:312-321`):
- 长时间任务每 15 秒刷新锁时间戳
- 防止正常运行的任务被误判为超时

**队列持久化**:
- 任务队列存储在文件中，进程重启不丢失
- 每次状态变更立即写入文件

## 四、完整并发流程示例

```
请求1(项目A) → 获取锁成功 → 启动心跳 → 执行翻译 → 释放锁 → 处理队列
                    ↓
              17语言并发翻译
                    ↓
              每语言50键/批
                    ↓
          缓存查询 → API翻译 → 二次修复

请求2(项目A) → 获取锁失败 → 加入队列 (pending)

请求3(项目B) → 获取锁成功 → 并发执行（与项目A同时进行）

请求1完成 → 释放锁 → 自动处理请求2
```

## 五、面试要点总结

### 双重翻译机制的价值

1. **缓存层**：减少 API 调用，提升性能和成本效益
2. **修复层**：提高翻译完整性，确保没有遗漏

### 文件锁+队列的价值

1. **原子性**：`fs.open("wx")` 保证锁获取的原子性
2. **隔离性**：项目级锁实现不同项目并发、同项目串行
3. **可靠性**：超时机制 + 心跳续租 + 队列持久化
4. **可观测**：任务状态追踪、队列位置查询

### 关键代码位置

- 锁机制: `util/index.ts:130-321`
- 队列管理: `util/versioning.ts:273-534`
- 翻译缓存: `util/translator.ts:542-566`
- 二次翻译: `util/translator.ts:462-537`
- 流程控制: `routes/i18n.ts:32-99, 477-538`

### 核心设计思想

这套机制确保了在高并发场景下，翻译任务既能充分利用资源（多项目并发、多语言并发），又能避免资源竞争（同项目串行、批次控制），同时具备故障恢复能力。
